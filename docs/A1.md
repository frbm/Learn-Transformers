## Research-engineering tricks

- **One int64 per window (Horner in base 256).** This turns n-gram counting into `np.unique`, which is one sort. Hashing and sorting replace a Python dict.
- **`searchsorted` as a join.** A lookup into a sorted key table is a vectorised hash join with no Python loop.
- **Context counts from the same windows.** Then Σ_c N(h,c) = N(h) exactly, and the conditionals sum to 1. The test `test_conditionals_sum_to_one` catches every normalisation bug.
- **Two code paths that must agree.** The vectorised `nll` and the per-position `next_logprobs` compute the same number in two ways. Use this pattern for every fast kernel.
- **Gumbel-max.** `argmax(z + G)` samples from `softmax(z)` with no normalisation and no `exp`.
- **Ratio of sums.** `BpbMeter` keeps totals. A mean of per-batch bpb is biased when batches have different byte counts.
- **Contiguous split.** A random split leaks overlapping n-grams into test.
- **Dtype assert.** `uint8 * 256` overflows silently. The assert in `window_keys` stops that.
- **Map-reduce counts.** `sharded_unique` counts by `key % k`. This is how you count when one array does not fit in RAM.
- **Gauss–Hermite quadrature** computes E_q[f] for a Gaussian q to machine precision with 80 points. Start the optimiser on both sides of the symmetric point, because one start can stay on the saddle.
