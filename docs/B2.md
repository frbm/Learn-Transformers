## Results

**Tests:** 11 pass, 1 strict xfail. The given test `test_quintic_keeps_singular_vectors_and_flattens` asks for every flattened singular value to be above 0.5. For a square Gaussian G, σ_min / ‖G‖_F ≈ 1e-5. Five quintic steps multiply a small value by at most 3.4445⁵ ≈ 490, so no correct implementation can pass the square case. It is a strict xfail: if it ever passes, the test fails and tells you so. `test_quintic_matches_scalar_iteration` checks the square case against the exact prediction of Proposition 3 instead.

**Exercise 2.** Smallest σ that φ^∘5 maps above 0.5: **cubic 0.0709, quintic 0.00107**. On [1e-2, 1], the quintic's output band is [0.68, 1.13]. It does not converge to 1, but it lifts small singular values 66× sooner than the cubic.

**Task 4** (smoke run, 150 steps, width 256, B 16 × T 256). Median of ‖ΔW‖₂ / ‖W‖₂ over time, per hidden matrix:

| | min | max | max / min | CV across matrices | final val loss |
|---|---|---|---|---|---|
| AdamW (lr 3e-3) | 1.4e-2 | 4.2e-2 | 3.1 | 0.27 | 7.07 |
| Muon (lr 0.02) | 1.7e-2 | 2.4e-2 | 1.4 | 0.10 | 6.45 |

Prediction confirmed: Muon's ratios are more uniform. Every Muon update has ‖O‖₂ ≈ 1 by construction, scaled by √(d_out/d_in), so ‖ΔW‖₂ is the same for every matrix of a given shape. AdamW's update is sign-like per entry. Its spectral norm depends on how aligned the signs are, which differs by layer.

Overheads under about 2 % are inside the timing noise; the 64k-token rows came out between −6 % and +2 %. The 5d/τ prediction counts the Newton–Schulz FLOPs against one matrix's training FLOPs only. It ignores attention, embedding and readout, so it overestimates once the GPU is busy.

**The bug this task found.** With one Newton–Schulz call per matrix, the overhead at d = 256 and 8k tokens was **51 %**, not 4 %. The step was launch-bound: 24 matrices × 15 small matmuls, each a separate kernel launch from Python. `Muon.step` now stacks the updates of each shape and makes one batched call per shape. The bake-off step count went from 204 to 322 in the same budget.

## Answers

**§1, rows 1 and 2.** Frobenius: ⟨G, Δ⟩ ≥ −‖G‖_F‖Δ‖_F by Cauchy–Schwarz, with equality at Δ = −ηG/‖G‖_F. Max norm: ⟨G, Δ⟩ = Σ G_ij Δ_ij ≥ −η Σ |G_ij| when every |Δ_ij| ≤ η, with equality at Δ = −η sign(G). The dual of ℓ_∞ is entrywise ℓ₁.

**Exercise 1.** cG = U(cΣ)Vᵀ has the same U and V, so polar(cG) = polar(G) for c > 0. Gradient clipping multiplies G by c ≤ 1, so it does not change the direction of a Muon step without momentum. With momentum, clipping still changes the weight of the current gradient against the buffer, and it changes the AdamW part (embedding, readout, vectors). Under Muon, clipping is mostly a no-op on the hidden matrices.

**Interview (60 s).** An optimiser is steepest descent under a norm. For a hidden matrix, the norm that measures how much a step changes the layer's output is the spectral norm (B1). Steepest descent under it is the polar factor UVᵀ of the gradient (convex duality: the dual of the spectral norm is the nuclear norm). This keeps the gradient's singular vectors and gives every direction the same step, so directions with small singular values learn as fast as dominant ones. Muon gets UVᵀ from momentum with a quintic Newton–Schulz iteration: five bf16 matmul steps, no SVD. It is only for hidden matrices. Vectors are not operators. The embedding's inputs are one-hot, so only one column moves per token and the operator geometry does not apply. The readout fan-out is the vocabulary. Those stay on AdamW.

## Research-engineering tricks

- **Batch small kernels.** At small width a step is launch-bound, not FLOP-bound. Stack same-shape matrices and make one call: here 51 % → 4 % overhead. Measure before you trust a FLOP model.
- **Block power iteration with Rayleigh–Ritz.** One-vector power iteration converges like (σ₂/σ₁)^(2k), and Gaussian matrices have σ₂ ≈ σ₁. The given test failed in 46 % of seeds. A block of 8 vectors plus a b × b eigenproblem fails in 0 of 200 seeds, at one (n, 8) matmul per iteration. Warm-start the block across calls.
- **An exact oracle in float64.** The cubic iteration converges to UVᵀ, so 40 float64 steps must match the SVD to 1e-6. A scalar replay of φ on the singular values tests the quintic exactly.
- **A strict xfail for a wrong given test.** Document why the spec's assertion cannot hold, keep the test, and mark it `strict=True`. Then an unexpected pass becomes a failure.
- **CUDA events, warm-up, then the median.** `time.time()` around asynchronous GPU work measures the launch, not the kernel.
- **Probes outside the timed region.** `UpdateTracker` runs in `after_step`. The `Trainer` closes its timing window before any callback.
- **Fair comparisons.** Tune each optimiser on its own lr grid. Compare at a fixed wall-clock budget over several seeds. Warn when an optimum is on the edge of its grid.
- **Transpose tall matrices** in Newton–Schulz, so that XXᵀ is the smaller Gram matrix.
