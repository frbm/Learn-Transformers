## Results

**Tests:** 5 pass in about 40 s. The bootstrap tests (200 refits) take most of the time. The FLOP formula equals PyTorch's `FlopCounterMode` count exactly (ratio 1.000) on the test model.

With total N, 6N underestimates by 6–9 %: the attention term n_ctx/6d. With non-embedding N, it misses the readout matmul, a factor of 4 at d = 128. At this scale the N convention matters more than the attention term.

**Sweep plan** (B = 16, T = 512): from 74 steps (C = 1e14, d = 512) to 19 399 steps (C = 3e15, d = 128). On the 23.2 M-token train split, d = 128 at 3e15 sees 6.9 epochs. That is beyond the ~4 nearly free epochs of Muennighoff et al., so the small models at the largest budget are data-limited. Run `prep.py` (~200 M tokens) first, or keep the `epochs` column of each row in view.

**Smoke runs only.** The full sweep, the real fit and the Tier 1 prediction are left for the user: about 30–60 min plus ~40 min of GPU.

- *Runner* (C = 1e13 and 3e13, d ∈ {128, 192, 256}, L = 4, B 8 × T 256): six runs, 110–810 steps, 2–15 s each. At every budget the smallest model wins: at such small C the optimum N is below the grid. Approach 2 needs a vertex inside the grid, so it reports nothing (`a = nan`). Approach 3 gives a = 0.36 with a 95 % interval of [0.02, 0.93]: six runs cannot pin five parameters, and the interval says so.
- *Synthetic sweep* (`fit.py --synthetic`, the 20 planned (N, D), true law E = 2, α = β = 0.3, 0.5 % noise): approach 2 gives a = 0.448. Approach 3 gives a = 0.699 [0.337, 0.821], α = 0.13 [0.06, 0.55], E = 1.16 [≈0, 2.13], and a tight β = 0.295 [0.272, 0.301]. This is the E–A–α degeneracy of §3: N spans one decade, so the fit trades a low E against a shallow α. The predicted Tier 1 loss, 3.258 [3.223, 3.317], still covers the true value (≈ 3.31). Predictions inside the data's hull survive a degenerate fit. Exponents do not.
- *Data prep* on 1 MB of text: the ids from `prep.py` are bit-identical to `data/fineweb.bin`, so the parallel and serial encoders agree.

**Bugs this review found.**

1. *The bootstrap collapsed to a point.* On the six real smoke runs, the best fit sits at E = 0, where exp(e) underflows to 0.0. The warm start then took log(0) = −inf, every refit returned the full-data fit unchanged, and the 95 % interval of a was [0.360, 0.360]: a zero-width interval from six runs. This is the failure that §3 attributes to the published Chinchilla fit. The warm start now clamps to the smallest normal float. `test_bootstrap_survives_a_boundary_fit` pins the six real runs, passes with the fix and fails without it.
2. *A pipeline test could block the real prediction.* `fit.py --synthetic --predict` wrote `runs/b4_prediction.json`, the same write-once file as the real Tier 1 prediction. One rehearsal would have locked out the real pre-registration. Synthetic runs now write `runs/b4_synthetic_prediction.json`.

## Answers

**Prediction protocol (Task 5).** `fit.py --predict` writes `runs/b4_prediction.json` with the date, the point estimate and the bootstrap interval. It refuses to overwrite an existing file. Copy it into the Experiments row before you run `--tier1`. Then `--check` reports the miss in units of the interval width. No prediction has been recorded yet, because the sweep has not been run.

**Exponent shift between conventions (expected).** Across the sweep, non-embedding N grows by ×22 (d = 128 to 512) and total N by ×9. The same losses therefore give a smaller α and a smaller IsoFLOP slope a with non-embedding N. On the synthetic sweep, approach 2 gives a = 0.448 (total) and 0.490 (non-embedding). Approach 3 gives about the same α for both, with very wide intervals. The real numbers come from `fit.py`.

**Interview (60 s).** L(N, D) = E + A N^−α + B D^−β with C = 6ND. Substitute D = C/6N and set u = log N. The loss is then a sum of two exponentials of opposite slopes, convex in u, with a unique minimum: N* ∝ C^{β/(α+β)} and D* ∝ C^{α/(α+β)}. The two exponents sum to 1, and the resource whose term decays more slowly gets more of the budget. Three things are fragile:
1. E, A and α are strongly correlated, so the marginal intervals are wide. Chinchilla's published intervals were implausibly narrow for ~400 runs (Besiroglu et al.).
2. Each point must be a run whose schedule ends at its own D.
3. The N convention and the 6N approximation move the exponents at small scale.

## Research-engineering tricks

- **An exact count, checked by an instrument.** `flops_per_token` matches `FlopCounterMode` to 0.0 %. The test uses naive attention, because the counter sees matmuls and not every fused kernel.
- **Token budgets from the exact count, not 6N.** Each run gets `steps = C / fpt / (B T)`, and the realised `C_exact` is logged.
- **Plan without building.** `mup_config` returns the `Config` of a sweep point, so the FLOP table and the plan never allocate a model.
- **Log-space parametrisation.** `log L̂ = logsumexp(a − α log N, b − β log D, e)` has no overflow and no sign constraints. The analytic gradient is softmax weights × clipped residuals.
- **Mind the boundary of a log parametrisation.** A parameter that the fit drives to its boundary (E → 0) underflows in the forward map. Clamp before you take the log again, or every warm start inherits a −inf.
- **A zero-width interval is a bug report.** No sampling interval from six noisy runs is exact. Test that intervals have width, as the given test does ("not implausibly narrow").
- **Vectorised grid screen.** All 4 500 Chinchilla initialisations are scored in one numpy pass (7 ms). L-BFGS-B starts only from the best 20.
- **Objective divided by δ.** The Huber sum is ~1e-5 otherwise, and the L-BFGS tolerances stop too early.
- **Warm-started bootstrap.** Each refit starts from the full-data fit plus two grid starts, at 0.15 s per refit. The extra starts guard against the wrong basin of a non-convex fit.
- **Percentile intervals, also for derived quantities.** a = β/(α+β) and the Tier 1 prediction get intervals from the same refits.
- **Resumable sweep.** One JSON line per finished run, keyed by (C, d, L, seed). A restart skips done keys, and nothing is held only in memory.
- **Pre-registration in code.** The prediction file is dated and write-once, and rehearsals write elsewhere.
- **Synthetic end-to-end check.** A fake sweep from a known law exercises the analysis pipeline before any GPU time.
- **Parallel tokenisation that keeps the order.** `Pool.imap` over document batches gives output bit-identical to the serial encoder. The file is read in 4 MB blocks, never as one string.
- **μP makes one learning rate legitimate.** The sweep uses B1's `param_groups` (per-kind `lr_mult`). The `Trainer` keeps each group's own base lr under the schedule.
