## Results

**Task 0.** 100.7 MB of text, 23.39 M tokens (4.29 bytes/token), largest id 16 383 < 2¹⁶. The validation split is 233 924 tokens = 1 002 624 bytes. With `uint16`, the file is 47 MB, not 187 MB as `int64`. Each batch sent to the GPU is 4× smaller before the `astype(int64)`.

**Task 6 (full run).** 7.15 M parameters, 1 525 steps × 16 384 tokens, 129 s, 193 k tok/s, peak 4.76 GiB. The **val bpb is 1.768** (loss 5.254). The best n-gram on the bytes of the same text (fitted on 21 MB) gets 2.286 bpb at n = 5. The transformer wins by 0.52 bpb. The run is slower than the course's "about a minute" because there is no `torch.compile` (C1).

**Task 7** (smoke run, T ≤ 2048; B = 8, n_q = 8, d_h = 64, bf16, fwd + bwd):

| T | naive ms | naive GiB | SDPA ms | SDPA GiB |
|---|---|---|---|---|
| 256 | 3.05 | 0.06 | 0.45 | 0.01 |
| 512 | 4.87 | 0.25 | 0.45 | 0.03 |
| 1024 | 19.2 | 1.00 | 1.59 | 0.06 |
| 2048 | 77.5 | 4.00 | 4.70 | 0.11 |

Log–log slopes: naive time 2.0, memory 2.0; SDPA time 1.7, memory 1.0. Prediction: the fp32 scores alone are B·n_q·T²·4 bytes, which is more than 12 GB at T ≈ 6 850. Measured, the naive path uses 4× the fp32 scores (scores, probabilities, their bf16 copy, gradients). So it fails earlier, near T = 3 500. Run `--T 4096 8192` to see the OOM.

**Task 8** (smoke run, **60 steps**, not 300). Relative consensus distance ‖H − 1h̄ᵀ‖/‖H‖ by layer:

| variant | at init, layers 1→8 | after 60 steps |
|---|---|---|
| full | 0.94 → 0.40 | 0.89 → 0.67 |
| no residual | 0.93 → 0.49 | 0.75 → **0.000** (σ₂/σ₁ = 0) |
| pure attention | 0.87 → **0.11** | 0.81 → 0.86 |

Prediction: both variants without the residual collapse, the pure-attention one fastest in depth. At initialisation this is true: pure attention shrinks geometrically, ×0.8 per layer. After training, the no-residual model collapses to rank one. The pure-attention model trains away from collapse in 60 steps, but its loss stays the worst (8.73, against 7.35 for the full block). Run the full 300 steps before you record numbers.

## Answers

**Interview (60 s).** An attention matrix is row-stochastic, so it is an averaging (Markov) operator. Repeated averaging contracts the rows to consensus at rate τ(A) < 1 per layer, and faster when the weights become uniform (Dong et al.). The identity path carries the token-specific part of H through every layer. Then each sublayer writes an additive correction to a shared stream. This makes the model deep without loss of token identity, and it makes circuit decompositions possible (E1).

## Research-engineering tricks

- **SDPA as the oracle, then as the fast path.** The naive path is the definition. It must match the fused kernel in fp32 (1e-5) and in bf16 (2e-2, the bf16 epsilon sets the tolerance).
- **GQA by broadcasting.** View q as `(B, n_kv, g, T, d_h)` and unsqueeze k, v. There is no `repeat_interleave` copy. SDPA gets `enable_gqa=True`.
- **The mask from absolute positions.** `tril(diagonal=q_offset)`. `is_causal=True` is wrong when T_q ≠ T_k, so the SDPA path gives an explicit mask in that case. A dedicated test compares naive and SDPA with an offset.
- **Softmax and norms in fp32 under autocast.** RMSNorm upcasts, then casts back before the gain.
- **Preallocated KV cache, written in place.** Concatenation per step costs O(T²) memory traffic. The cache test uses prefill, a chunk of 8, and single steps, because the chunk is the case where the offset matters.
- **Parameter count derived on paper.** `expected_params` is a formula, tested against `numel()`.
- **Pad the vocabulary to a multiple of 64** (tensor-core tiles). SwiGLU hidden size `round_up(8d/3, 64)`.
- **uint16 memmap and one fancy-index gather** of `(B, T+1)`. x and y are views of the same buffer. `pin_memory` + `non_blocking`.
- **Fixed validation windows.** The same windows at every evaluation, so that curves compare. bpb comes from the validation bytes/tokens ratio.
- **Synchronise before you read the clock.** Do one warm-up call before you measure.
- **Forward hooks** collect activations without a change to the model.
