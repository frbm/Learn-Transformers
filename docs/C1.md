**Task 5 (Tier 1, B 16 × T 1024, profiler on).**

| | GPU ms/step | matmul share | idle | top kernel |
|---|---|---|---|---|
| eager | 242 | 26 % | 4.1 % | — |
| compiled | 154 | 62 % | 1.6 % | bf16 GEMM 128×128 (14 %), cuDNN flash attention backward (10 %) |

Eager, three quarters of GPU time goes to non-matmul kernels: norms, SiLU, RoPE, the softmax of the loss, casts. All are memory-bound (I < 1). Fusion is the only lever, and compile moves the matmul share from 26 % to 62 %. The profiler's own overhead inflates the absolute times; use the shares, and time steps without it.

**Task 6 (smoke runs only: 30–40 steps of the Tier 1 configuration on the 23 M-token A3 data).** The 200 M-token run (~40 min compiled) is left for the user. Prediction written to the log before the first step: peak 7.58 GiB, roofline bound 0.112 s/step, 32.0 M parameters, 3.97 TFLOP per step.

| | step time | tokens/s | MFU (P = 66.7) | peak memory |
|---|---|---|---|---|
| eager | 0.218 s | 75 k | 0.27 | 7.84 GiB (predicted 7.58: −3.4 %) |
| `--compile` | 0.094 s | 175 k | 0.63 | 3.34 GiB |

Compile gives 2.3× on this card. Two predictions miss, and both misses are instructive:
- **The compiled step beats the "lower bound".** `roofline_step_time` charges the activation traffic of eager mode (four passes over every saved byte). A fused graph moves far fewer bytes, so the bound holds for eager only. Eager runs at 1.95× the bound.
- **The compiled step uses 2.3× less memory than predicted.** The predictor counts what eager PyTorch saves (65d bytes per token per layer at Tier 1). Inductor's fused kernels save close to Proposition 2's bound (34d) and never materialise the full logits in fp32.

## Answers

**Exercise (Tier 1 fits?).** 18N = 0.54 GiB static (32.0 M parameters, with the bf16 autocast copies). Eager activations are 4.13 GiB (65d bytes per token per layer: Proposition 2's fused bound is 34d), and logits 3.03 GiB (12 bytes per logit). Total ≈ 7.6 GiB at the start of backward. It fits in 12 GB without checkpointing, with ~3.5 GB free for the CUDA context, the desktop and fragmentation. Measured: 7.84 GiB.

**Open question: the largest term the memory model missed at first.** Eager mode saves far more than the fused bound: 65d against 34d per token per layer. RMSNorm saves its fp32 input and its normalised output. Every `nn.Linear` under autocast saves its own bf16 cast of the same input (three for q, k and v). QK-norm saves fp32 and bf16 copies. The MLP saves silu(a) and the product separately. The second is the logits: 12 bytes per entry at the start of backward (saved fp32 log-softmax, incoming and outgoing gradients), as large as all eight layers together. `layer_bytes_per_token` and `logits_bytes` list each tensor, so a snapshot can be checked line by line.

**Measured P and β against the derivation.** 66.7 TFLOP/s is 94 % of 71 (the SM × clock scaling of the 4090 whitepaper holds). 403 GB/s is 80 % of 504: a single `copy_` does not saturate GDDR6X.

**Interview (60 s).** Training memory has three parts. A fixed 16N bytes (fp32 weights, gradients, two Adam moments), plus 2N for the bf16 copies under autocast. The activations that autograd saves, ∝ B·T·L·d. The logits, ∝ B·T·V, which at a 16k vocabulary are as large as all the layers. At small scale, activations and logits dominate, so tokens per micro-batch is the knob, with checkpointing and chunked CE as the tools. FlashAttention does more FLOPs (it recomputes P in backward) but is faster: softmax attention is memory-bound. Streaming the softmax as a ratio of two sums with a running max lets it keep blocks in SRAM. It never writes the T × T scores to HBM: Θ(T²d²/M) HBM accesses instead of Θ(T²). On a GPU, bytes moved, not FLOPs, set the time of everything except large matmuls.

## Research-engineering tricks

- **Validate a benchmark by its result, not by its conditions.** The first `runs/c1_bench.json` had P = 29 TFLOP/s, measured while other jobs shared the GPU. Every MFU after it would have been ~2× too high. `nvidia-smi` utilisation cannot detect this: the desktop alone shows 10–20 %. `load_peaks` now rejects smoke files and any P below 70 % of the derivation, and it warns when it falls back.
- **Pin the attention backend.** The Windows wheels have no flash kernel, and the memory-efficient kernel rejects `enable_gqa`. Without a priority list, SDPA silently picks the math kernel: it stores the (B, h, T, T) scores and is 13× slower. `attention_sdpa` sets cuDNN first, which takes GQA natively.
- **Count bytes op by op, and keep the count in code.** `layer_bytes_per_token` lists every saved tensor with its size. When the measurement disagrees, a memory snapshot (`--snapshot`) shows which line made the tensor that the model lacks.
- **The peak is a moment, not a sum.** `predict_peak_memory` takes the max of the start of backward, the backward of the last block, and the optimiser step.
- **A prediction is a model of one mode.** The eager predictor misses the compiled peak by 2.3×, and the eager roofline is not a bound for a fused graph. State the mode with every number.
- **Chunked CE that actually saves memory.** Checkpoint each chunk's readout + loss, so backward recomputes the logits one chunk at a time. Divide by the loss-bearing tokens of the whole input.
- **Token-weighted accumulation.** Count the loss-bearing tokens of the whole step before any backward. Then sum the losses and divide once (Proposition 8).
- **Exact resume.** The checkpoint holds the model, the optimiser states, the step, the data position and four RNG states. It is saved through a temporary file and `os.replace`, so a crash during the save keeps the old one. A test kills a run, resumes it, and compares the next losses with an uninterrupted run.
- **No host sync in the inner loop.** Losses stay on the GPU. The `Trainer` synchronises once per logged step.
- **CUDA events for timing.** `time.time()` around asynchronous GPU work measures the launch.
- **Write the prediction before the run.** `experiments.c1.train` logs the predicted peak, the roofline step time and the epoch count as the first line of `log.jsonl`.
